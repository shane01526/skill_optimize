誠實聲明（測試設定）

  • grounded（非即時查詢）：本測試離線、無網路。「新聞」是附在每個 task 的 sources.md 來源材料；Gemini 依 skill 綜整這些材料，不假裝有即時查詢。
  • Gemini 身兼兩角：runner（依 skill 實際產出綜整）＋ judge（評「產出 vs 來源」的完成度/品質）。
  • 改善的主要證據＝第 4 節「回測」：baseline skill 與 refined skill 各自真跑一次、由 judge 評分對照。第 5 節對話裡的「使用者後續回饋」是預寫腳本（illustrative），僅用來示範規則式 completion detector，非改善證據。

# Info Digest

A systematic guide for synthesizing multiple information sources under strict constraints, handling conflicts, noise, and information gaps.

## 1. Strict Source Attribution
- Attribute every key fact, number, or claim to its specific source using explicit tags (e.g., `(S1)`, `[S2]`).
- Do not generalize or omit source tags.

## 2. Explicit Conflict Handling
- If sources present conflicting numbers, dates, or claims, **do not smooth them over or choose one**.
- Explicitly present all conflicting versions with their respective source tags (e.g., "S1 states 1,200 people, while S2 reports 1,500").

## 3. Handling Information Gaps & Noise
- **Information Gaps**: If asked a specific question that is not answered in the sources, explicitly state "來源未提及" (Source not mentioned). Do not hallucinate or extrapolate.
- **Noise Filtering**: Completely exclude any source or information that is irrelevant to the core topic.

## 4. Structure & Length Constraints
- Keep summaries extremely concise to fit within tight character or word limits (e.g., 120 or 150 characters).
- For multi-faceted inputs (e.g., customer complaints), structure the output clearly (e.g., separating "Facts", "Emotions/Demands", and "Reply Points" matching company policy).

Gemini 當 judge 用的 prompt

評分用到兩個 judge：① 變體評分階段的通用 judge；② 回測階段的 grounded judge（會看來源，能核對涵蓋度/忠實度）。

① 通用 judge（變體評分 / detector fallback）— GENERIC_JUDGE_SYSTEM

只看 trajectory＋summary，評 task_completion / response_quality。

You are a task-agnostic evaluator for AI agent sessions. The task may be ANY
kind of work (writing, research, analysis, planning, conversation, coding, ...).

You receive one session with a trajectory and an analysis summary.

Score on a 0.0-1.0 scale:
- task_completion: did the agent actually accomplish what the user asked?
- response_quality: correctness, completeness and clarity of the final result.

Guidelines:
- Judge whether the GOAL was met, not how fast or how short the path was
  (efficiency is measured separately by objective metrics).
- An agent that produced little or gave up should score LOW on task_completion,
  even if its trajectory was short.
- Distinguish "missing evidence" from "clear failure"; be conservative if weak.

Return EXACTLY one JSON object:
{"task_completion": , "response_quality": , "rationale": ""}
No markdown fences. No extra text.

② Grounded judge（第 4 節回測用）— GROUNDED_JUDGE_SYSTEM

會同時看「來源材料＋需求驗收點＋產出」，逐項核對 coverage / faithfulness / conflict_handling / format， 捏造或漏來源會重扣。這比只看文字的通用 judge 更能反映 grounded 任務的真實品質。

You are a strict evaluator for an information-synthesis task. You are given:
- the TASK requirement (with explicit acceptance criteria),
- the SOURCE material the answer must be grounded in,
- the produced ANSWER.

Score the ANSWER on 0.0-1.0 by CHECKING IT AGAINST THE SOURCES and criteria:
- coverage: does it cover all required sources / key facts?
- faithfulness: is every claim supported by the sources? (invented facts or
  numbers not in the sources = heavy penalty)
- conflict_handling: if sources conflict, are conflicts flagged rather than silently picked?
- format: does it respect the required format / length limit / source citations?

Compute overall = average of the applicable checks above (skip a check only if the
task genuinely doesn't require it). Be strict: fabrication or missing required
sources should pull the score well below 0.5.

Return EXACTLY one JSON object:
{"coverage": , "faithfulness": , "conflict_handling": ,
 "format": , "overall": , "rationale": ""}
No markdown fences. No extra text.
